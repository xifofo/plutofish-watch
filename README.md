# PlutoFish Watch

独立的可视化目录监控客户端。每个根目录预先绑定一个 PlutoFish 作品、季（剧集）和网盘目标，版本可自动归类或固定选择；发现本地新视频后，等待文件稳定，再通过 PlutoFish 完成上传、核验和资源登记。

## 启动

独立仓库：`xifofo/plutofish-watch`。在本仓库根目录执行：

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm start
```

开发使用 `pnpm dev`。构建环境使用 Node.js 22.12+、pnpm 10.8.1；运行测试还需 Bun、ffmpeg 和 ffprobe。如果终端遗留了其他 Electron 项目的 `ELECTRON_RENDERER_URL` 或 `ELECTRON_RUN_AS_NODE`，先移除这两个环境变量。

上传、ED2K 和片段校验实现以完整源码快照保存在 `vendor/publisher/`，与下载器源文件逐字节一致；`source-lock.json` 保存来源基线和文件 SHA256，构建前检查快照完整性。安装、开发、构建和运行均不依赖相邻下载器仓库或 GVS 网关。共享引擎的更新方法见 [快照说明](vendor/publisher/README.md)。

本机路径保留在 PlutoFish 工作区的 `tools/plutofish-watch/`，具有自己的 `.git`、依赖锁和提交历史，主仓库不收录内部文件，也不加入 `dev.sh` 默认启动链。服务端 API 改动仍归 PlutoFish 主仓库；客户端单独提交、推送和发布。首次提交和推送完成前不登记 submodule 指针。

## 部署桌面客户端

客户端应安装在能直接读取监控目录的电脑上，需要桌面会话。可以监控已挂载的磁盘或网络目录；应用运行期间需保持路径可访问。当前没有无界面服务器或 Docker 部署模式，也不会注册系统服务或开机自启动。

### 部署前准备

- PlutoFish 服务端已部署，并包含下文 [数据与服务契约](#数据与服务契约) 列出的接口；为客户端准备完整发布端凭据及已授权的 115 源账号。客户端不需要单独部署数据库或 GVS 网关。
- 客户端电脑能访问 PlutoFish 服务和上传目标。远程服务地址必须使用 HTTPS；仅 `localhost`、`127.0.0.1`、`[::1]` 支持 HTTP 开发连接。地址填写服务根地址，如 `https://plutofish.example.com`，不要附加 `/api/v1` 或后台页面路径。
- 目标电脑安装 `ffprobe`。macOS 已安装 Homebrew 时可执行 `brew install ffmpeg`，再用 `ffprobe -version` 检查；Windows/Linux 安装包含 ffprobe 的 FFmpeg 后，可在“连接与设置”中手动选择可执行文件。应用包不捆绑 ffprobe。已打包的客户端运行时无需 Node.js、pnpm 或 Bun。

### macOS 本机安装与启动

在本仓库根目录构建应用目录：

```sh
pnpm install --frozen-lockfile
pnpm run pack
```

Apple Silicon 的产物为 `release/mac-arm64/PlutoFish Watch.app`，可以直接启动：

```sh
open "release/mac-arm64/PlutoFish Watch.app"
```

也可在完全退出旧版后，把整个 `.app` 拷贝到“应用程序”目录：

```sh
ditto "release/mac-arm64/PlutoFish Watch.app" "/Applications/PlutoFish Watch.app"
open "/Applications/PlutoFish Watch.app"
```

Intel Mac 构建使用 `--x64`，对应应用目录通常为 `release/mac/`。当前配置为未签名构建，适合本地验收；对外分发前需配置签名、公证并验证安装体验。

### 生成安装包

先执行 `pnpm install --frozen-lockfile` 和 `pnpm build`，再运行对应打包命令。macOS 包在 macOS 构建；Windows x64 包也支持在 Apple Silicon Mac 上交叉构建：

| 目标平台 | 打包命令 | 安装方式 |
| --- | --- | --- |
| macOS Apple Silicon | `pnpm exec electron-builder --mac dmg --arm64 --publish never` | 打开 `release/` 中的 `.dmg`，把应用拖入“应用程序” |
| macOS Intel | `pnpm exec electron-builder --mac dmg --x64 --publish never` | 同上 |
| Windows x64 | `pnpm run pack:win:x64` | 运行 `release/PlutoFish-Watch-<版本>-windows-x64-setup.exe` |
| Linux x64 | `pnpm exec electron-builder --linux AppImage --x64 --publish never` | 为 `release/` 中的 `.AppImage` 添加执行权限后运行 |

`pnpm run pack` 只生成可运行的应用目录；上表命令生成安装包，并明确禁止自动发布。当前已验收 macOS arm64 应用目录；Windows x64 已完成安装包构建和内容校验，仍需在 Windows 上验证安装、启动与运行；DMG、Linux 安装包仍需构建和验证。Linux 保存凭据还需要可用的系统密钥环。

Windows 包面向 Intel/AMD 64 位系统（x64）；当前 Electron 运行时不提供 32 位 x86 包。`pack:win:x64` 会先构建源码，再生成包含版本号与架构的 NSIS 安装程序；不捆绑 ffprobe，也不会自动上传 GitHub Release。

构建配置固定使用 `toolsets.nsis: 1.2.1`，包含 Apple Silicon 原生编译器，避免旧默认工具需要 Intel Mac 运行环境。未配置 Windows 代码签名证书时生成的安装包不带数字签名。

### 首次运行、升级与恢复

1. 打开“连接与设置”，填写服务地址与完整发布端凭据，点击“保存并连接”，确认发布端已验证、视频检测显示“可用”。
2. 按下文 [使用](#使用) 添加监控目录、作品和上传目标。“自动归类”可在无匹配时创建版本；需要首次补传时保留“首次补传历史文件”勾选。
3. 关闭主窗口后仍在托盘监控；要停止应用，请使用托盘菜单“退出”。应用退出或电脑休眠期间停止处理，下次启动会补扫。
4. 升级前从托盘完全退出，备份下文说明的应用数据目录，再替换应用包。保留 `watch-state.json` 和 `publications/`，才能继续沿用扫描基线、查重记录和上传断点。开发模式与安装版默认使用同一数据目录，勿将正式数据目录作为测试环境。
5. 跨机器迁移时重新配置发布端凭据；加密凭据依赖原机器的系统密钥环。目录路径与访问权限也需重新核对，不能只复制应用包就恢复原监控。

常见问题：

| 现象 | 检查方式 |
| --- | --- |
| 视频检测显示“需要配置” | 确认 `ffprobe -version` 可执行，或在设置中选择 ffprobe 的完整路径 |
| 服务连接失败、返回非 JSON 或接口不存在 | 检查根地址、HTTPS 证书、发布端凭据及服务端接口版本 |
| 片名搜索不可用 | 检查服务端是否支持 `publisher/tmdb/search`，以及后台的 `tmdb.apiKey`；也可直接填写 TMDB ID |
| 退出后目录不再监控 | 保持应用运行；当前没有开机自启动，需要登录系统后手动启动 |

## 使用

1. 在“连接与设置”填写 PlutoFish 服务地址和完整发布端凭据。客户端通过发布端接口鉴权，仅显示授权源网盘。
2. 确保本机安装 `ffprobe`，或在设置中选择其可执行文件。客户端不会自动下载执行工具。macOS 自动查找 Homebrew 路径，Linux 查找标准路径，Windows 支持 `C:\ffmpeg\bin\ffprobe.exe` 或手动选择。
3. 添加本地目录，选择资源分类、电影／剧集、季号和源账号，按片名搜索 TMDB。选中后自动填入作品名称和 TMDB ID；仍可直接填写 ID。新增目录默认“自动归类”，无匹配时自动新增版本；“固定版本”需要选择已有版本。已有监控记录保留固定版本行为。
4. 选择网盘目标目录，或填入目录 ID（`0` 为根目录）。浏览网盘会通过 PlutoFish 读取真实网盘目录。
5. 设置文件稳定等待时间（默认 30 秒、最小 10 秒），选择“首次补传历史文件”，点击“创建并开始监控”。如首次未勾选，之后可在监控目录点击“补传历史”，只把当初忽略的文件加入队列；重复点击不会重复建任务。
6. 如需释放本地空间，在“连接与设置 → 本地文件”开启“自动删除本地文件”，设置保留天数并保存。默认关闭，天数预填 7 天，可设 1–365 天。
7. 已创建的目录点击“编辑”，可修改路径、作品、季号、版本方式、来源预设、源账号、网盘目标和稳定等待时间。未开始发布的文件重新按新配置归类；已开始或完成的任务保存原配置，重试与重启不改变归属。目录原来的监控／暂停状态和人工暂停决定保持不变。更换本地路径会停止旧路径中尚未开始发布的任务，并按“首次补传历史文件”重新扫描新路径；仍在原路径的已登记文件继续原任务，但不再参与新路径的自动清理。原目录的历史补传仍使用列表中的“补传历史”。

支持文件格式：MP4、MKV、M4V、MOV、AVI、TS、M2TS、WebM。第一版只发布视频，不发布字幕、NFO 或图片。

剧集按 `S01E02`、`E02`、`EP02`、`第2集` 识别集号。多集合并、季号不匹配或无法确定时进入“待确认集号”。目录绑定不会根据后续文件自动切换作品或季。

自动归类读取真实分辨率、视频编码、动态范围、帧率和默认音轨，与同作品同季的已有版本匹配。唯一匹配时复用；规格明确且无匹配时，通过下载器共享的文件登记流程创建并发布新版本，电影、首集和历史中间集均支持。与下载器共用规格标签和版本匹配器，兼容旧版本缺失音轨标签；版本名称补齐真实媒体规格，保留来源和特殊标签。稳定发布键不含本地目录、集号或文件名，因此后续集数、跨监控目录和重试复用同一版本。

来源按“文件名优先 → 目录预设补缺”确定，不再默认 `WEB-DL`。创建时可展开“目录来源预设”，已有自动归类目录可点击“来源预设”。网络片源（`WEB-DL` / `WEBRip`）需要平台标签，如 `YOUKU`、`TX`、`NF`；确实不区分平台时可明确填写 `WEB`。`BluRay`、`REMUX`、`HDTV`、`DVD` 可不填平台。文件名与预设不同，采用文件名明确声明的值；缺失字段才用预设。

来源仍不明确时进入“待确认来源”，可逐文件补填后重试，也可选择已有版本。修改目录预设会重试缺少来源的待确认任务；已确认的版本和上传任务保持原归属。旧目录不会自动添加来源预设。

文件名与实际规格矛盾、媒体信息不完整、多个同规格版本或已有同名版本资料冲突时进入“待确认版本”，可选择已有版本或修正后刷新。已下架的绑定不能通过自动新增绕过。归属及新版本规格随文件任务持久化；重启接续原发布键。1080p 与 4K 可在同一目录分流，查重仍按各自版本与集号进行；同版本同集的不同内容会停止提示。

## 监控与恢复

- 原生递归文件事件触发补扫，另每 3 秒进行一次异步完整扫描；新建目录、移动进入的完整目录及离线新增文件均能发现。不支持原生递归通知时继续使用定期扫描。
- 剧集上报使用“第 N 集”作为缺失集标题的默认值；升级到 0.1.2 后，旧版漏传集标题导致 HTTP 422 的未完成任务会补齐标题，沿用原任务键、序号递增和上传断点。校验失败显示具体接口与字段名称，不展示供应商原始响应；ED2K 刷新不会清除尚未恢复的同步错误。
- 只处理普通文件，跳过隐藏目录、隐藏文件、符号链接及 `.part`、`.tmp`、`.temp`、`.download`、`.crdownload` 临时文件。不能添加重复或嵌套的根目录，也不能监控应用数据目录及其父目录。
- 首次选择“不处理已有文件”时，完整扫描成功后保存基线。重启沿用基线；离线新增文件仍会发现，旧文件内容修改会作为新内容处理。
- 稳定检测根据文件身份、大小和修改时间的连续观察执行；检测、SHA1 计算前后再次核对。稳定窗口不能保证一个暂停写入很久的外部程序已经完成，建议下载器先使用临时扩展名，完成后再改为最终文件名。
- 按服务地址、源账号、版本、集号和完整 SHA1/大小查重，文件名和本地根目录不参与内容身份。原任务的本地文件仍在时跳过重复副本；原文件已移走时重新登记本地校验能力，远端内容仍可复用。
- 新任务先查询服务端版本和稳定绑定；已有版本继续检查文件内容，覆盖下载器已上传、其他监控客户端已上传和本地历史丢失的情况。尚未创建的新版本通过首次资源登记建立绑定，服务端按发布键幂等复用。同版本同集的不同内容停止待处理；查询失败不会当作“尚未上传”继续。
- 源网盘已有相同内容时，服务端核验原远端文件，跳过上传初始化和字节传输；核验失败停住等待处理。资源上报在版本锁内合并相同内容，避免重复文件和重复就绪事件。
- 复用文件仍走公共发布流程：登记任务、核验、资源回执、计算并补记 ED2K，以及接收服务端的片段校验通知。ED2K 状态显示在任务中，可展开复制链接；已上传与 ED2K 已同步分别展示。监控器保持运行且原文件可读时，可接替已关闭的下载器提供本地校验。
- 文件被替换或移走时停止旧的未完成任务。挂载或子目录不可访问时保留已有记录，不把一次扫描失败当作整批删除。
- 断网、连接超时或临时服务故障后自动重新验证连接，按 5、10、20、40、60 秒间隔重连，持续至恢复；健康连接每分钟复核一次。离线启动和电脑唤醒后同样适用，无需重新输入已保存的凭据。
- 版本查询、网盘浏览和目录保存遇到慢请求时，仍可在“连接与设置”重新验证连接；重连会取消旧请求，避免等待旧请求超时。自动恢复提示也会显示在添加目录页面；取消的目录保存需要手动再次提交。
- 临时网络故障、限流和服务暂不可用导致的上传失败自动重试：从 5 秒开始递增，最长间隔 5 分钟；服务端指定 `Retry-After` 时至少等待该时长。重试次数、下次时间和分片检查点落盘，重启后继续原任务。界面显示下次时间，可“立即重试”或暂停。
- 凭据失效、权限撤销、文件改变或丢失、版本与内容冲突等需人工处理，不无限重试。修正凭据后重新连接；修正任务后点击“重试”。升级前遗留的失败记录没有结构化错误信息，需手动重试一次才能进入新的自动恢复流程。
- 暂停目录会停止该目录的发现与上传，恢复后补扫；“暂停上传”保留目录发现。网络恢复不会解除目录暂停、全局上传暂停或手动任务暂停，已取消任务不会复活。
- 0.1.3 补齐目录编辑与恢复边界：延长稳定等待会重新检查未登记文件；暂停任务修改季号后可继续进入集号确认，已登记任务不能改集号。异常退出时本地取消／失败决定优先于旧上传进度；启动检测不再重复验证用户刚完成的连接。侧栏显示实际版本号，沿用编辑前配置的任务显示原作品与上传目标。
- 未完成发布保存分片检查点，恢复前重新检查本地文件。完成回执未知时沿用现有引擎核验原任务；不会直接重新上传整份文件。
- 默认保留本地原文件。启用自动清理后，从上传完成时间起算保留天数；完成回执已确认、ED2K 已生成且服务端已确认保存后，才允许删除。开启或缩短天数也会作用于已完成文件，已到期文件在下次清理时处理。关闭或延长天数对尚未删除的文件立即生效，重启不会重置计时。
- 自动清理复用下载器引擎：每分钟检查到期任务，删除前确认原文件身份，跳过被替换的文件、符号链接、仍在读取的文件和不属于有效监控目录的任务。暂停目录、暂停上传、移除监控或断开连接时暂缓自动删除。仅删除对应视频，不清空文件夹、字幕、NFO 或网盘内容；本地重复副本若只被标记为“重复已跳过”，不会自动删除。
- 清理后保留任务历史与 ED2K 链接，界面显示“本地文件已清理”。通过 `range-proofs/forget` 通知服务端撤销该文件的本地片段校验资格；通知失败保留发布清单，网络恢复或重启后补发。
- 关闭窗口保留托盘监控，退出应用停止任务。第一版不注册系统服务或开机自启动；电脑休眠、应用退出期间靠下次启动补扫。

## 数据与服务契约

运行数据存储在 Electron 的独立 `userData` 目录：macOS 默认 `~/Library/Application Support/PlutoFish Watch/`。包含：

- `watch-state.json`：目录绑定、扫描基线、文件任务、暂停状态与本地文件保留策略。
- `connection.json`：服务地址与系统密钥环加密的发布端凭据。Linux 无可用密钥环时拒绝明文保存。
- `publications/`：独立的上传检查点、进度快照、ED2K 与片段校验清单。

这些文件不进入 Git。数据解析或落盘失败时停止处理，不以空队列覆盖损坏记录。`--watch-data=/绝对路径` 可为本地验收指定隔离数据目录。

客户端使用 `publisher/me`、`publisher/tmdb/search`、`publisher/releases/query`、`publisher/directories`、`publisher/tasks/report`、`publisher/uploads/prepare`、`publisher/files/check`、`publisher/files/report`、`publisher/files/ed2k` 和 `publisher/range-proofs/*`。上传通过现有临时 OSS 凭据直传，PlutoFish 负责鉴权、目标账号与上传调度、核验和目录登记。

片名搜索要求服务端支持 `publisher/tmdb/search`，并在 PlutoFish 后台配置 `tmdb.apiKey`。TMDB 密钥留在服务端；搜索只读资料，不访问网盘或创建作品。旧服务端会提示更新，仍可手填 ID。

需要先更新 PlutoFish 服务端：新增 `files/check`，支持 `files/report` 的可选 `deduplicate: true`，并支持远端文件复用及复用任务的 ED2K 补记。下载器共享发布引擎也发送该去重标记。旧服务不支持这些请求时会明确失败；不能把查重失败当作不存在。本次查重功能不新增数据库迁移。

资源登记沿用现有发布器的 `autoPublish: true`。本地子目录用于发现文件，新文件上传到绑定的固定网盘目录，不创建同名网盘目录树。复用源网盘已有文件时保留原远端位置和名称，不为新绑定目录另造副本。
